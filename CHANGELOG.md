## [Unreleased]

### Added
- **Autostart for the watch supervisor: `watchd install` / `uninstall` / `installed` (110).** The supervisor that keeps the fleet's watchers alive now survives logout, reboot and upgrades: `install` registers the platform's own entry — a systemd user unit `~/.config/systemd/user/squeezr-watchd.service` (`Restart=on-failure`, `RestartSec=5`, `StartLimitIntervalSec=60` + `StartLimitBurst=5` named in `[Unit]` so a broken binary comes to rest in `failed` instead of flapping forever), a launchd agent `~/Library/LaunchAgents/dev.summonasync.squeezr-watchd.plist` (`RunAtLoad` + `KeepAlive`/`SuccessfulExit=false`), or a `schtasks` Task Scheduler task `squeezr-watchd` with `/SC ONLOGON` (deliberately an on-logon task, not a service; no Windows service is documented or claimed) — baking in the launch pair the entry can actually exec (`--autostart` appended; the dotnet-muxer shape names the muxer with the assembly as its payload argument) and refusing an unlaunchable program at install. Under `--autostart` the supervisor retires on a binary upgrade: on drift it exits **75** at the top of the next sweep without touching the fleet, and the retire unlocks only after at least one full useful fleet sweep has completed earlier in this process's lifetime (`EX_TEMPFAIL` — non-zero so `Restart=on-failure`/`KeepAlive` retry it, outside the 0–3 verdict ladder `watchd installed` owns; 0 would freeze the fleet on the old code); `WatchdRestartPolicy` allows self-retire only on platforms whose entry brings the process back, so a Windows-logon-started supervisor keeps its binary to the next logon. The upgrade fleet policy is the owner ruling from review-110-08, stated plainly: systemd's default `KillMode=control-group` takes the whole fleet down with the retire (~`RestartSec` 5 s + the new instance's immediate first sweep, children relaunch on the new binary), while on launchd children survive and the new supervisor reads them `SkippedLiveOwner` — `managed elsewhere` — until each dies on its own. `installed` is a read-only instrument panel: one `key=value` line per dimension (`status`/`platform`/`unit`/`present`/`enabled`/`failed`/`loaded`/`program`/`arguments`/`program-state`/`watchd`/`pid`/`hint`/`note`) and the exit ladder 0 installed / 1 not-installed / 2 broken (`installed-but-binary-missing`, `unit-failed`, `present-but-not-enabled`) / 3 no verdict (`probe-unsupported`, `probe-unknown`), where a platform that cannot answer a dimension prints it instead of letting the healthy verdict spend it. `install` reads the live-lock holder first and warns about the collision per platform without taking, stealing or killing anything; `uninstall` removes only the managed entry, keeps repeat runs an exit-0 no-op with an honest stderr line, and refuses exit 0 when the platform would not confirm the removal. The release path is wired too: `install-release.sh` restamps the unpacked binary (`touch` — archived mtimes give the drift detector nothing to see), asks the new build `watchd installed` and rewires the entry onto the new tag and restarts the supervisor, closing each step with a machine-readable `autostart=` line (`rewritten+restarted`, `rewired+restart-failed`, `touched`, `skipped:no-new-build|touch-failed|autostart-not-installed|install-failed`); a hand-untarred release restamps nothing, so the manual case is documented as "restart it yourself" (`watchd install` from the new binary re-points the entry — it names the concrete install path, not the `~/.local/bin` symlink). Two operator traps are documented in the README: systemd user units die with the session without `loginctl enable-linger` on a headless box, and the parked-in-`failed` unit recovers via `systemctl --user reset-failed` rather than waiting out the declared window. **Contract additions (declared per 035):** three new commands (`watchd install`, `watchd uninstall`, `watchd installed`) with their exit ladders (`installed`: 0/1/2/3 as above; `install`/`uninstall`: 0 success and honest no-op, 1 refusal), one new command option (`watchd --autostart`) and one new process exit code (75 on upgrade retire), the `autostart=<outcome>` machine lines on `install-release.sh` stdout, and OS-surface files the tool owns (`squeezr-watchd.service`, `dev.summonasync.squeezr-watchd.plist`, task `squeezr-watchd`); existing commands, envelopes, exit codes and the `watchd` default-command behaviour without the flag are untouched. README gains the autostart section; the Windows legs (the ONLOGON lifecycle, the live `schtasks /Query /XML` shape of `Settings/Enabled` and `/TR` inside `<Exec>` closing review-110-07 MINOR / review-110-06 MINOR-2) sit on the windows-checklist owner gate.
- **Rust is symbol-aware (111).** `.rs` files leave the text-fallback lane and join the tree-sitter line next to JS/TS: `LanguageDetector` maps `rs`→`rust`, the provider parses with the bundled Rust grammar (`TreeSitter.DotNet 1.3.0`, no new dependency — grammar binaries ship for all nine runtimes), and symbol/ref extraction became **per-language tables** (`TreeSitterLanguages` home — unknown languages extract nothing loudly instead of silently borrowing the JS table). A Rust file yields functions, structs, enums, unions, traits, impl blocks, modules, type aliases, consts, statics and macro definitions as symbols — trait-methods (`function_signature_item`) and nested containers included, impl blocks named `Trait for Type` — and `use` trees, free/method/scope-path calls, trait/impl targets and macro invocations as references, pool-isolated per language so JS edges never bind onto same-named rust rows. `symbol_lookup`, `find_references` and `code_search` answer against Rust repos on par with JS/TS; the RustMini fixture crate carries the agent-surface e2e. Doc comments are a known gap (`///` pipeline, tracked in BUGS/021); Python and Go follow on 023.
- **Python and Go are symbol-aware (023).** `.py` and `.go` files leave the text-fallback lane and follow rust onto the per-language tables in the `TreeSitterLanguages` home: `LanguageDetector` maps `py`→`python` and `go`→`go`, both parsed with the bundled TreeSitter.DotNet grammars — no new dependency. Python yields functions (an `async def` is one function row that keeps the keyword in its signature), classes, methods and UPPER_SNAKE module/class constants, and a decorator belongs to the definition under it — the row's span starts at the `@` line while the signature stays on the `def` line; go yields functions, methods named by their receiver (an unnamed `func (*Registry) All` and a generic `func (g *Generic[T]) Get` included), structs, interfaces, type declarations, aliases and package-level consts and vars, with two stated refusals: a blank identifier and a multi-name const/var spec name nothing. The reference pools grew from two to four — python and go each got their own wall, because tree-sitter grammars collide on node-kind names (`function_declaration` means different shapes in js and in go) and a same-named twin across grammars must never bind across the wall. Import rules stay each language's own spec, no shared dotted helper: `import a.b.c` binds the TOP package `a`, `from x import *` binds the module itself and no individual name behind the star, while `import "net/http"` binds the LAST element `http` with an explicit alias winning over it. `symbol_lookup`, `find_references` and `code_search` answer against the PyMini and GoMini fixture projects on par with JS/TS and rust — 24 e2e facts measured by real indexing, including the decoy-leaf guard (a dotted import and a same-named local symbol produce zero false-positive edges) and per-file symbol/chunk/ref pins. README's language matrix and the skill doc now name the shipped vocabulary and the gaps that stay: doc comments (rust `///`, python docstrings, go `//`) remain indexed as text only — one tracked defect, BUGS/021. Full suite serial green 3733/0; hard review series `audits/review-023-01..08`.
- **The pre-read hook sees Qwen too, and `mcp install` arms it (114).** `tool_name` in a PreToolUse payload carries the *runtime's own id* — Qwen sends `read_file`, Claude sends `Read` — and the hook compared the literal `Read` in two places, so a Qwen bulk read produced neither a nudge nor a telemetry row: the adoption signal that calls this hook the product's strongest surface described exactly one runtime. Both comparisons now answer through one declared set (`HookPreReadToolNames`: `Read`, `read_file`, `ReadFile`) compared Ordinal-exact with no normalization — an unmeasured id stays silent rather than being lowercased into something nobody verified — and `Read`/`ReadFile` ride as Qwen-side *matcher aliases* while the payload Qwen delivers still says `read_file`, which is why the armed Qwen pattern is the anchored `^read_file$` (Qwen evaluates matchers as regex; Claude matches the exact tool name). The advice keeps its JSON shape (`hookSpecificOutput.additionalContext` beside `hookEventName: "PreToolUse"`) and that shape is the point: the Qwen aggregator collects `additionalContext` without requiring `permissionDecision`, so the text lands in the model's context, while bare text on stdout at exit 0 reaches the human as a UI `systemMessage` and never the model. Arming moved off the hand-pasted snippet onto the command: `mcp install` writes one managed `PreToolUse` entry per verified runtime (Claude `Read` in `~/.claude/settings.json` — a different file from the `~/.claude.json` server entry; Qwen `^read_file$` in the same `~/.qwen/settings.json` that carries `mcpServers`, `hooks` as an additive sibling key), `mcp doctor` reports the state it measured on disk, `mcp remove` strips it. Kimi Code and Codex CLI stay `not armed (hook layout unverified)` — nothing is invented for a layout nobody verified; `mcp install --project` alone (block-only mode, no clients) arms nothing, and there is no flag that skips the arm — it rides with the client registration. "Managed" is defined strictly: equality with the command install computes, or `<exe> hook pre-read` with the executable named `squeezr` — which makes the pre-feature hand-applied snippet managed, so install normalizes it to canonical form and remove takes it back. Merge-safety, at the proven altitude: foreign entries under `PreToolUse` are preserved by canonical serialization and whole-file byte-identity is proven against the canonical pre-image — the JSON round-trip reformats the file (same posture as the direct config writer), a foreign shape the merge cannot resolve refuses the write before the file is touched, and a second install writes neither the block nor a `.bak` (the `.bak` a re-install does leave comes from the server-entry write, the hook upsert staying silent because the block is already canonical). **Contract changes, widened value domain (declared per 035):** `params.tool` on `queries.jsonl` hook rows still records the verbatim `tool_name` the payload carried — no field added, none renamed, no meaning changed — so what widens is the *set of values the key takes*: from `Read` alone to whatever a connected runtime names its read tool, with rows written before this build staying `Read`-only. Read every runtime label at face value: a `Read` row is called Claude Code because that is what the row says, not because any other host was ruled out — the label table is a reading rule, not a matcher, and it lives on the CLI side (`UsageCommand`) while Core holds no runtime names. **Contract additions (declared per 035):** `usage --json` `totals.sessions` gains `hookSessionsByTool` (one bucket per verbatim recorded name, ordinal-ordered, distinct sessions per bucket) and `hookSessionsWithoutTool` — buckets are *observed under this name* and may overlap (one session that read through two tools is counted in both), they are not exhaustive, and they must never be summed to obtain `hookSessions`, which stays the distinct denominator the adoption ratio divides by; `hookSessionsWithoutTool` counts the distinct sessions whose rows named no tool at all and sits outside the per-tool list; the human adoption line names both measured runtimes plus an `unrecorded tool name` side, at zero included. `mcp install --json` and `mcp remove --json` gain additive `hooksArmed`/`hooksRemoved`, `mcp doctor --json` an additive per-entry `hookStatus` (`armed` / `armed (project scope)` / `not armed` / `not armed (hook layout unverified)`), and the human doctor prints one `hook pre-read: <state>` line per client. The install line and its `hooksArmed` key claim a state, not a write: they are true for any client whose hook layout resolves, so an idempotent re-run still says armed having moved no byte — `doctor` is what answers the disk. `stats` and its `--json` shape are untouched; the `hook pre-read` command help no longer names one runtime's tool. The live proof of this feature caught one defect sitting in its own path, and this same release train fixes it: a payload that quoted its numbers (`"offset":"437","limit":"400"`) was unreadable to the input deserializer and muted the hook — advice and row both (`BUGS/028`, resolved by 114/T6, next bullet); the live-proven delivery remains the whole-file read, and the quoted-number arms are proven by the in-process A/B carrier rather than a re-run live session — no doc claims more. Verification (T5, docs-and-help only): `dotnet build` 0 errors / 41 warnings (the post-017-merge baseline, nothing added); `Mcp.Onboarding|HookPreRead|Usage` slice 410 passed / 0 failed / 0 skipped on a fresh pinned `SQUEEZR_HOME`; the single code line is the command description and the old string is pinned by no test (`grep` across `tests/` for it finds nothing).
- **A hook payload that quotes its numbers is readable (`BUGS/028`, 114/T6).** Qwen forwards the model's raw tool arguments and this model writes them as strings, so a paged read arrived as `"offset":"437","limit":"400"`; the default `System.Text.Json` reader refuses a string token for a numeric property, both deserialization sites in `hook pre-read` threw into their fail-open catchers, and the whole hook — advice and adoption row both — went silent on every Qwen page-read (measured live: 17 calls, 1 row). The payload now binds through one shared `JsonSerializerOptions` with `NumberHandling = JsonNumberHandling.AllowReadingFromString`, and nothing wider: quoted non-digits (`"wide"`, `"400abc"`, `""`) still throw, truncated bodies and wrong-root bodies still fail open with no output, and the `limit` boundary is honored *through* the new binding — `"399"` stays quiet, `"400"` produces the byte-same nudge the numeric arm produces plus a telemetry row shaped exactly like the numeric arm's. **Contract addition (declared per 035):** the accepted `tool_input` shape widens — `offset`/`limit` may arrive as quoted decimal integers; every previously accepted payload answers unchanged. Verification: red-first on the new string-shape pins (8 failed / 65 passed before the fix, transcript `audits/t6-028-fix-2026-11-12/`), then `dotnet build --no-incremental` 0 errors / 41 warnings and the `Mcp.Onboarding|HookPreRead|Usage` slice 431 passed / 0 failed / 0 skipped on a fresh pinned `SQUEEZR_HOME`; the live A/B carrier replayed against the fixed binary answers 347 bytes of nudge and one ledger row on the string arm.

### Removed
- **The ONNX-CPU embedding line is gone (109).** Local ONNX inference is removed wholesale: `OnnxEmbeddingProvider`, `OnnxInferenceSession`/`IOnnxSession`, `OnnxExecutorEvidence`, the BPE/WordPiece text encoders, the `Microsoft.ML.OnnxRuntime` dependency, the bundled `bge-code-v1` tokenizer assets, the `fetch-model.sh`/`.ps1` downloaders, the installer model-presence step and the `Models\**` content include. Supported embeddings providers are now `ollama` and `openai` (any OpenAI-compatible endpoint); `auto` resolves through the Ollama probe and — with nothing answering — fails with an explicit hint instead of falling back to ONNX. A workspace still configured with `embeddings.provider = onnx` refuses to load with a typed migration error naming the remedy, and `doctor`/`status` surface the same case as a `fail` finding carrying the migration path: switch the provider, then run a full `squeezr index --reembed` — vectors across embedding models are incompatible, old ones are dropped, no conversion exists, and vector search degrades until the re-embed completes. **Contract additions (declared per 035):** the `onnx_provider_removed` error code on config load (replaces the generic `workspace_error` on the query/index/serve paths — same messages, typed code), the additive `embeddings provider` doctor finding rendering the ONNX-store migration path as a `fail` (and the same path riding `status --json` warnings); release archives no longer ship onnxruntime binaries (~28 MB lighter per target); the `embeddings.onnx` config section is gone — unknown-provider errors list `ollama, openai, auto`.

- **watchd supervision tells the truth (113, T1-T6 = `35d7a56` `b032d5f` `d54e1b4` `3338d57` `43d5a34` `e1fbc06`).** The 110 lane's follow-up debt, declared against the shipped code. `fleet restart`'s "reset the wedged flag" stopped being a lie: the crash-loop wedge marker persists in `~/.squeezr/watchd/state.json` as an additive `wedged` key (absent from the JSON while no store is wedged — the writer emits null and the file options drop null keys — so a clean fleet writes byte-for-byte the pre-113 shape; an old binary reading the new key ignores it), the supervisor's `CrashLoopGuard` memory is a cache over that file, and `fleet restart` clears the wedge for real — it writes the wish back to `running`, takes the marker out of the file, and a live supervisor releases the store and hands out a fresh restart budget on its next sweep. ### Security
- **Installing the update does not remove a previously indexed secret from an existing store: nothing leaves `~/.squeezr/workspaces/<storeKey>/` until the next index pass or `squeezr compact` actually runs.** A reinstall keeps the store intact on purpose, so rows a pre-guard index wrote — the content, the path names in `meta.db` and `trigram.idx`, and the paths recorded as parameter values in `queries.jsonl` — are still on disk after the upgrade. What the new binary changes immediately is only the read path: protected rows are never served, never listed and never rendered again, and ingestion refuses such paths from then on. The data itself leaves at one of two moments: the **next index pass** (`squeezr index`, watch passes included — protected paths are no longer walked, so their rows go through the ordinary deletion cascade with deferred vector reaps), or **`squeezr compact`**, the explicit operator route and the only command that additionally redacts the path names the deferred-reap journal kept, scrubs `queries.jsonl` parameter values through the same classifier (repo-qualified and absolute shapes folded back to the stored form first), rewrites `trigram.idx` and rebuilds `meta.db` to reclaim the bytes. There is no `--purge` flag and no background wipe: the guard sweep is part of every `compact`, and no store is ever purged without an index pass or a deliberate `compact`. Both routes report their purge in **counts only** — no path name and no secret value appears in a purge report, an index counter, a drop warning, a `--json` field or a telemetry line (`secret guard: 7 path(s) purged, 186 row(s) removed · 1 reap journal name(s) redacted · 28 recorded parameter value(s) redacted · 7 point cleanup(s) queued`), and a secret value never reaches any output at all. The one place a protected name is spoken is the read side, and the two shapes differ: an explicit refusal echoes the path that was asked (`'.env' is protected by squeezr's built-in secret guard…`), while the withheld tally names **the first result the guard dropped — which the asker often did not name** (`secret guard: 3 result(s) withheld ('.env' matches built-in patterns)`: a `repo_map` scoped to a prefix names a file under it, an unscoped one names a protected path no argument ever carried), and `find_references` on a symbol whose declarations are all protected refuses with the **first** protected declaration file instead of lying "No symbol named 'X' in the index". The refusal wording says *built-in* even when an `indexing.secretGuardExtra` mask decided the case; only the tally distinguishes the origin. Raw-byte proof over a pre-guard store: `audits/store-purge-2026-10-05.md`.
- **The built-in set cannot be narrowed by configuration.** The only knob is `indexing.secretGuardExtra` (union-only), and the shapes that would subtract — `!negation`, comments, dir-only forms, unsupported residuals — are inert by construction: they never compile into the mask set. Character classes and `\` escapes (063/T14) can only widen a mask. Documented boundaries of the classifier, stated rather than left silent: it decides on the **last path segment**, so a path shaped like a *directory* named `.env` (`.env/dev`) is not covered (a trailing separator is trimmed, so `.env/` still refuses), and `id_rsa*` matches public `.pub` keys too — over-protection is the chosen failure mode.
- Closes the three guard limits that 1.0.8 shipped as open work: rows staying in older stores, `squeezr tui` map naming protected files, and deny-at-ingestion for the index pass.

- **A watch-pass deletion no longer orphans Qdrant points silently.** Watch/serve passes run without a vector store, so every file they removed left its vectors in the collection forever and nothing was recorded: a removal that could not reap now lands in the `pending_reaps` journal (only for files that actually held vectors) and is replayed by the next pass that carries both a store and an embeddings provider. `index --json` and the `--events` `completed` line carry `deferredReaps` (files this pass queued) and `pendingReaps` (what the journal still holds); `serve --watch` — which ran with no status sink at all and therefore dropped every pass report — writes one `watchPass` reap line to stderr as soon as that queue is nonempty. **`--json`/`--events` contract additions (declared per 035).**
- **A deferred reap can no longer destroy a live file's vectors.** `MetaStore` hands out `max(_id)+1`, so a freed file id is recycled by the next file the walk adds — and the journal keyed reaps by that id alone: replaying it deleted the *new* owner's points and reset its honest markers, spending the entry on an impostor while the deletion it owed stayed unreaped. Journal entries now carry the repo+path the reap was queued under; when a live row answers to a different file, the entry is dropped and the report names `squeezr vectors reconcile --apply` as the route that reaches those points by hash instead of by id.
- **`index --full` and `squeezr compact` dropped store rows without a cascade.** The trigram rebuild path removed `files` rows for repositories gone from the manifest and for files missing on disk while leaving their chunks/symbols/refs behind (the coverage denominator kept counting them) and their points behind (orphaned, unreported). That path now goes through the same drop as every other deletion: cascade plus reap-or-journal, so no removal route skips the vector cleanup any more.

### Added (043, watch fleet + daemon heartbeats)
- Running watch daemons (`squeezr watch`, `serve --watch`) now write a heartbeat file into the workspace store dir — `<storeDir>/<kind>.heartbeat`, kind = `watch` / `serve-watch`: `{pid, kind, startedAt, lastBeatAt}`, refreshed every 5 s and after each successful catch-up pass, atomically, removed on clean exit
- `squeezr fleet [--json]`: registry-wide daemon overview — per workspace, both daemon kinds (alive: pid + uptime; dead: marker kept and shown, never cleaned), pending chunks and last full index from meta.db (best-effort, `n/a` when unavailable), stale rootPath warnings on stderr; works from any CWD, no workspace required
- `squeezr fleet stop <storeKey>`: stops both daemon kinds (SIGTERM → 5 s grace → SIGKILL on Unix, process-tree kill on Windows); heartbeat pids are verified before signaling — process must look like squeezr (name/cmdline match + start time vs heartbeat `startedAt`), refusing to touch foreign or reused pids; no alive daemons → `not-running`, exit 0
- `squeezr fleet restart <storeKey>`: restarts the CLI `watch` daemon only — stops it if alive, then spawns a detached `squeezr watch` with cwd = workspace root; a live `serve --watch` errors with the MCP hint (the MCP client owns it); stop/restart accept `--json` (NDJSON result, clean stdout per the 035 contract)

### Added (021, token stats + query telemetry)
- Query telemetry: every navigation command (CLI `search`/`symbol`/`refs`/`map`/`expand` and all six MCP tools) appends one line to `queries.jsonl` in the workspace store dir — `ts`, `sessionId`, `tool`, `params`, `tokensUsed`, `truncated`, `hits`, `durationMs`, `cacheHit`, `indexAgeSeconds`; a CLI process is one session, an MCP connection gets its own; append failures are swallowed (telemetry must never break a query), unreadable lines are skipped on read; failed commands record nothing
- `squeezr stats [--json] [--reset]`: per-tool table (count, avg tokens, truncation rate), counterfactual savings — actual `tokensUsed` vs reading every expanded file whole (each file counted once, size-based estimate consistent with the chunker, files missing from the index reported separately), serve-cache hit-rate across sessions, covered period; `--json` emits a single camelCase object (035 contract), `--reset` truncates telemetry (`{"reset":true,"recordsRemoved":N}` in JSON mode, human line `Cleared N telemetry record(s).`); retention hint past 50k records, no auto-rotation by design
- MCP response caching: `repo_map`, `code_search`, `symbol_lookup`, `find_references` cache responses per serve session — LRU 100, canonical-JSON key (recursive property sorting, null-vs-absent equivalence); the cache generation is derived from meta.db mtime, so any reindex (watch pass or external `squeezr index`) invalidates all keys; hits return the stored envelope unchanged and are marked `cacheHit: true` in telemetry; `expand_span` (live file reads) and `index_status` are not cached

### Removed (029, dead config)
- `gitAware` config key and its TUI editor field removed — the key existed since M2 but was never read by any code path (indexing is always a full SHA-256 diff walk, freshness is handled by the read-time guard and watch mode); the dead `lastIndexedCommit` LiteDB field in `RepoDocument` is gone with it; existing configs that still carry `"gitAware": ...` keep loading (unknown keys are skipped, covered by a regression test)

### Changed (030, install hardening)
- `scripts/install.ps1` accepts `-Rid win-x64|win-arm64` (default win-x64) and wipes `artifacts\publish` before publishing, so switching RIDs can't leak binaries from a previous publish into the install dir (parity with install.sh); post-install embedding-model check now matches install.sh — warns to run `fetch-model.ps1` when no model is found in the central store or the install dir

### Added (031, CI publish smoke)
- CI `publish-smoke` job: single-file self-contained publish for linux-x64 and win-x64 on every push to main and on PRs, then a smoke run of the published binary (`squeezr --version`) on the matching runner — publish regressions surface on regular pushes instead of during a release cut; `cache: true` dropped from both CI jobs (setup-dotnet cache needs `packages.lock.json`, which the repo does not use — review-029-030-031-01 W1)
